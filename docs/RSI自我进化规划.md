# RSI：建模系统的自我进化规划

> 目标：让 AI CAD 建模系统从**自己的**建模结果中学习——评判器筛出好结果，从好结果中抽取 workflow，扩充动作空间与经验，再用来提升下一代的建模效果。
> 本文档取代《实施路线与CAD-1K及论文计划》中的 W3（工具挖掘与准入），并修正其中“在 held-out 上验证后入库”的做法（held-out 只报告、不参与任何决策）。

---

## 0. 结论先行

- **进化的对象是技能库，不是模型权重。** LLM 固定不变（当前为 Qwen3.5-397B-A17B，经 AI Ping 调用），进化的是：宏工具（由现有 L1 工具组合而成）、建模经验卡、错误修复提示、检索用的示范轨迹。思路与 Voyager / DreamCoder / LILO 同源，但动作空间是原生参数化 CAD，评判有精确几何 GT。
- **评判器必须先变硬。** 现有打分主要看包围盒、体积区间和特征数量，存在“体积碰巧对、形状错”的空子；拿它做进化信号会学会迎合指标。进化开始前必须补上**与参考实体的体积 IoU**和拓扑/特征核对。
- **训练题必须程序化生成、GT 由构造保证。** CAD-1K 只用来决定“出哪些零件族”；dev 只用于准入决策；held-out 与 heldout2 永久冻结，每代只报告。
- **最小可行版本**：2–3 个零件族、3 代、每代约 100 道训练题，单代 API 成本十几元量级。成功标准是冻结 held-out 与**未见零件族**上的稳定提升，而不仅是训练族上的提升。

## 1. 定义与边界

### 1.1 “自我进化”在本项目中指什么

一次进化 = 一“代”（generation）：

```
出题 → 用当前技能库建模 → 评判 → 选出好轨迹 → 抽取候选技能 → 准入验证 → 更新技能库 → 下一代
```

每一代产出一个带版本号的技能库 `lib/gN`，所有评测结果都标注所用的库版本。

### 1.2 可以自动进化的内容

| 类别 | 形式 | 运行时如何生效 |
|---|---|---|
| 宏工具 | 声明式 JSON：参数表 + 由现有 L1 工具组成的步骤模板 + 前置/后置条件 | 作为额外工具出现在 Agent 的工具列表中；执行时展开成 L1 调用，逐步走现有事务与回滚 |
| 经验卡 | “情境 → 做法”短条目，如“悬空凸台先建偏置基准面再拉伸回实体” | 按零件特征检索，少量注入系统提示（有 token 上限） |
| 错误修复提示 | 错误码 + 上下文 → 修复方式 | 附加到对应错误码的 hint 字段 |
| 示范轨迹 | 已验证的成功轨迹（参数化后） | 按特征签名检索相似题，作为少样本示例 |

宏工具**只能组合已有工具**，不执行任意代码，因此不会引入新的安全面，也不会绕过事务校验。

### 1.3 必须人工把关的内容

- 新的 C# 原子能力（扫描、筋、编辑特征、异形孔等）：进化只输出“缺口报告”，由人来实现。
- 评判器代码与阈值：每一代开始前冻结，进化过程不能修改。
- held-out / heldout2 的题目与 GT。
- 零件族模板（出题器）的新增：人写，或 LLM 提议 + 人审。

### 1.4 暂不做

- 权重更新（拒绝采样微调 / STaR 类方法）。当前 API 不支持微调；将来若换开源模型，进化产生的高质量轨迹可以直接作为 SFT 数据，这是自然的延伸，但不在本期范围。

## 4. 组件设计

### 4.1 TaskForge：程序化出题器

**零件族模板**是一段 Python：参数采样范围 + 约束 + 题面渲染 + 参考几何。

```python
class Family:
    name = "flanged_boss"                 # 族名，用于划分
    tags = ("revolve_or_stack", "hole_pattern")
    def sample(self, rng) -> dict: ...    # 采样尺寸，保证可制造（壁厚、孔距、不相交）
    def brief(self, p, rng) -> str: ...   # 多种措辞模板随机组合；可选 LLM 改写
    def reference(self, p) -> list[dict]: # 参考实体的构建步骤（直接调用 L1 工具，不经 LLM）
    def analytic(self, p) -> dict: ...    # shapely / 解析公式算体积、包围盒、孔位等
```

要点：

- **GT 双重校验**：参考实体由确定性脚本直接在 SolidWorks 中建出，同时用解析法独立算体积与包围盒；两者一致（相对误差 < 0.1%）才收录该题。这样工具本身的 bug 不会悄悄污染 GT。
- **措辞多样化**：同一组参数随机选择描述方式（给总高还是给各段高、给直径还是半径、给孔距还是孔到边距离）。若用 LLM 改写题面，改写后必须重新抽取全部数值并与原参数逐一比对，不一致即丢弃。
- **难度分级**：D1 单特征族 → D2 多特征 → D3 需要基准面 / 镜像 / 圆弧 → D4 多个零件族组合。每代按上一代通过率自动调整各级比例（通过率 > 80% 的级别降权）。
- **防近重复**：生成的训练题与任何 held-out / heldout2 题做特征签名比较（包围盒比例、体积比、特征类型多重集、孔数），过近则丢弃。

**零件族划分**（族级别，而不是题级别）：

| 划分 | 用途 | 来源 |
|---|---|---|
| train 族 | 生成训练题 | 由 CAD-1K 高频母题启发，自写模板 |
| val 族 | 生成准入用验证题 | 与 train 族同分布但参数、措辞独立采样 |
| unseen 族 | 每代报告泛化 | 人写，进化全程不生成训练题 |
| 现有 dev / held-out / heldout2 | dev 做准入，其余只报告 | 已有 |

首批候选族（均为自拟，只借鉴 CAD-1K 的母题频率）：法兰凸台、叉耳 / 支座、带孔底板、阶梯轴 / 套、管件、双圆弧连杆、带筋支架（等筋工具就绪后）。unseen 族首批：轴承座类、摇臂 / 曲柄类（与 demo / heldout2 同族，因此不能进入训练）。

### 4.2 Judge：评判器

分四层，进化信号以 J1/J2 为准：

| 层 | 内容 | 需要 |
|---|---|---|
| J0 | 现有 v2：包围盒、体积区间、结构细节 | 已有 |
| J1 | 与参考实体的**体积 IoU**：两实体在同一坐标系下求交与并，IoU = V(∩)/V(∪) | 新增 C# 接口：载入参考零件为实体，做组合（交 / 减）后读体积 |
| J2 | 拓扑与特征核对：各类面数、圆柱面直径与轴线的多重集、孔位（容差匹配）、实体数 = 1 | 基于现有 `model-observation` |
| J3 | 过程质量：工具调用数、报错次数、回滚次数、token、耗时 | 轨迹日志 |

- **朝向处理**：题面通常不规定坐标朝向。J1 先用包围盒主轴对齐，再在 24 种轴向排列 / 翻转里取 IoU 最大者；这个“最大化”只在评判器内部做，Agent 看不到 GT。
- **好轨迹的判定**：J1 IoU ≥ 0.98 且 J2 全部通过，才算“正确”；在正确的轨迹中，再按 J3 排序，选步骤少、报错少的作为抽取来源。
- **防被钻空子**：
  - 评判器代码与阈值每代冻结，版本号写入结果。
  - Agent 运行时只能拿到自身模型的观测，拿不到任何 GT 信息。
  - 每代随机抽 10 条被判为“好”的轨迹做人工抽检（看截图），记录误判率；误判率 > 5% 时暂停进化、先修评判器。
  - 保留 J0 分数一同报告，用来展示“只用 J0 做信号会发生什么”（见 6.2 消融）。

### 4.3 轨迹库

每条轨迹规范化存储：

```json
{
  "task_id": "...", "family": "flanged_boss", "split": "train", "lib": "g1",
  "judge": {"iou": 0.995, "j2_pass": true, "steps": 7, "errors": 1},
  "steps": [
    {"tool": "extrude", "args": {"plane": "top_plane", "loops": [...], "depth": "$p.flange_t"}},
    ...
  ]
}
```

数值参数尽量**符号化**：与题面参数相等的数值替换为 `$p.xxx`，可由题面参数线性表达的替换为表达式（如 `=$p.H-$p.t`）。这是后续把轨迹片段泛化成宏的关键。

### 4.4 Miner：抽取

1. **宏候选**：
   - 把正确轨迹变成“工具名 + 抽象参数形态”的符号序列（如 `ref_plane(face,+d) → extrude(ref,circle,-dir)`），跑频繁子序列挖掘（PrefixSpan，最小支持度按族数计：至少在 2 个零件族中出现）。
   - 对每个高频子序列，让 LLM 把若干具体实例归纳成一个带参数的宏：名称、说明、参数表、步骤模板（参数用表达式）、前置条件（如“需要已有实体”）、后置条件（如“体积增加”）。
   - 限制：步骤 2–6 步；参数 ≤ 8 个；不得包含具体数值常量（除 0、±1、90 这类结构常量）。
2. **经验卡**：取成功轨迹中的“报错 → 修正”片段，让 LLM 概括为“情境 → 做法”，按错误码与零件特征聚类去重；只有在 ≥ 3 条轨迹中被验证有效的才成为候选。
3. **示范轨迹**：每个零件族保留 J3 最优的若干条，按特征签名索引，供检索。
4. **缺口报告**：对失败轨迹，按“卡住的工具 + 错误码 + 所需几何能力”聚类，输出按频次排序的原子工具缺口，交给人工排期（与 CAD-1K 挖掘出的缺口互相印证）。

### 4.5 Gate：准入

候选技能依次通过三关才进入 `lib/g(N+1)`：

1. **重放**：宏在其来源轨迹对应的训练题上展开执行，结果必须与原轨迹一致（J1 IoU ≥ 0.98）。
2. **新训练题 A/B**：在新采样的 val 族题上，同一批题分别用“当前库”与“当前库 + 该候选”各跑一次（配对比较）；要求正确率不降，且步数或 token 显著下降（配对 bootstrap，95% CI 不跨 0），或正确率显著上升。
3. **dev 无回归**：在 dev 15 题上，加入全部新候选后的库的平均分不低于当前库的 CI 下界。

库的维护：

- 规模上限：宏 ≤ 12 个，经验卡 ≤ 20 条，注入提示的经验部分 ≤ 800 token。
- 淘汰：连续两代使用率 < 5%，或被新宏覆盖（功能上是其子集）则移入 `retired/`，保留记录。
- 所有准入与淘汰决定写入 `library/changelog.json`，带证据（A/B 数字）。

### 4.6 运行时

- 新动作级别 **L1+Lib(gN)**：L1 工具 + 该代库中的宏工具；系统提示追加检索到的经验卡与 1 条示范。
- 宏调用在日志中同时记录宏名与展开后的 L1 步骤，便于统计使用率、定位失败。
- 宏展开的每一步仍走现有事务：失败会回滚本次宏已建的所有特征，并把出错步骤、错误码返回给 Agent。

硬性规则：

- held-out、heldout2、unseen 的任何轨迹不进入轨迹库；评测脚本对这些划分默认不落盘轨迹细节到库目录。
- 出题器模板提交前做近重复检查（4.1），检查结果随模板一起提交。
- 每代的 held-out 结果只在该代的库冻结**之后**运行。

## 6. 实验设计

### 6.1 主实验

- G0 = 当前 L1（无库）；G1–G3 为三代进化后的库。
- 每代报告：train / val 正确率（J1+J2）、dev、held-out、heldout2、unseen 族的 v2 分数与 J1 正确率，以及平均步数、报错数、token、成本。
- 主图：代数 → held-out / unseen 正确率曲线（含 95% CI）；辅图：库规模与宏使用率随代数的变化。

### 6.2 消融

| 消融 | 目的 |
|---|---|
| 以 J0 代替 J1+J2 作为好轨迹判据 | 展示弱评判器导致的“迎合指标”与 held-out 退化 |
| 不经 Gate，所有候选直接入库 | 说明准入机制的必要性（库膨胀、工具选择干扰） |
| 只要宏 / 只要经验卡 / 只要示范 | 各类技能的贡献 |
| 库迁移到另一模型（如更小的模型） | 验证技能库是可迁移的“工程知识”，而不是对某个模型的适配 |
| 训练族数量 1 / 2 / 3 | 泛化到 unseen 族与训练族多样性的关系 |

### 6.3 成本估算

- 每代：训练题 100 × 1 次 + val A/B 约 40 × 2 次 + dev 15 × 2 次 + 报告（held-out 12 + heldout2 4 + unseen 20）× 2 次 ≈ 280 次运行。
- 按 ¥0.10–0.16 / 次，约 ¥30–45 / 代；抽取阶段的 LLM 归纳调用另计，预计 < ¥5 / 代。三代合计约 ¥100–150。
- 时间：单次运行约 1–4 分钟，SolidWorks 只能串行，每代约 8–12 小时，适合夜间批跑；每跑完一个零件文档立即关闭。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 评判器被钻空子 | 训练分数涨、held-out 不涨或下降 | J1+J2 双判据；人工抽检；J0 消融作为对照 |
| 过拟合训练族 | unseen 族无提升 | 族级划分；宏须跨 ≥ 2 族出现；报告 unseen 族 |
| 库膨胀 / 工具选择干扰 | 工具越多正确率越低 | 规模上限、准入 A/B、淘汰机制 |
| 宏过于具体 | 宏等于某道题的解 | 禁止具体数值常量；参数化表达式；跨族支持度 |
| 生成题分布太窄 | 题面措辞单一，Agent 学会套模板 | 措辞多样化 + LLM 改写 + 数值一致性校验 |
| 原子能力不足导致进化停滞 | 失败集中在少数几何能力上 | 缺口报告驱动人工补工具（编辑特征、成形到面、筋、异形孔、扫描） |
| 成本与时长 | 单代十小时量级 | 夜间批跑；先小规模（2 族、50 题）验证信号再放大 |
| SolidWorks 稳定性 | 长批次卡死、内存上涨 | 每题关闭文档；批次间重启服务；超时自动跳过并记录 |
